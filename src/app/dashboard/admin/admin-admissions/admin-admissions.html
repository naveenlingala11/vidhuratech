Manual Admissions & Enrollment Controls - Administrator Manual

1. Manual Admission Flow

Manual admissions are used when payments are collected offline (Cash, Direct Bank Transfer, UPI payments) and the administrator needs to provision access immediately. The flow triggers five backend events:

  • Account Search/Creation: The system searches for the email. If not found, a new Student account is generated with role STUDENT and a placeholder temporary password.
  • Credential Dispatch: A secure password reset token link is generated and sent via email, allowing the student to set their secure password.
  • LMS Enrollment: The student is enrolled in the selected training batch. This links their profile to courses, calendars, and assignments.
  • Invoice Generation: An invoice is saved in the database reflecting the amount paid, payment method, verification timestamp, and outstanding balances.

2. Financial Integrity & Verification

Invoices are generated instantly on submission. It is critical to configure payment indicators correctly to prevent discrepancy in accounts:

  • PAID Status: Marks the invoice as fully paid. Sets remaining balance to ₹0 and flags the payment verified state as true.
  • PENDING Status: Flags the invoice as unpaid. The student is granted platform access, but billing indicates outstanding dues.
  • PARTIAL Status: Records partial collections. The invoice is generated with outstanding amounts, allowing tracking of payment installments.
  • Offline Channels: Select UPI for QR code payments, BANK_TRANSFER for corporate wires, or CASH for in-hand collections.

3. Automatic Subsystem Synchronization

Creating an admission synchronizes three decoupled databases modules (User management, Lead tracking, and LMS Course structures):

1
Lead Tracking Integration

A lead is automatically created with status "Joined" and source "ADMIN_MANUAL_ADMISSION". This updates the sales funnel statistics in real-time.

2
LMS Notification Dispatch

Decoupled alerts notify both the student and the batch's primary instructor, listing batch access instructions and classroom links.

3
Account Security Link

New profiles require the student to click the password setup link in their email. If mail fails, they can trigger a reset using the public recovery portal.

4. Troubleshooting & Maintenance Runbook

  • "Student already enrolled in batch": If this occurs, the student is already linked to the training batch. The backend skips creating duplicate enrollments but generates a new invoice if needed. Verify their status under the batch directory.
  • Email SMTP Failures: In cases where network firewalls block the outgoing setup password email, the UI will display a MAIL_FAILED telemetry flag. Instruct the student to visit the login page and click "Forgot Password" to trigger a reset manually.
  • Invalid Email Formats: The form enforces syntax rules on the student's email. Verify there are no trailing whitespace characters or double domains (e.g. .com.com) before submitting.
